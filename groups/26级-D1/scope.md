# scope.md — minisearch 的边界

这份文件说明：这个工具给谁用、吃什么、回答什么、做到什么程度算通过、以及**明确不做什么**。写不清楚的地方，验收时一律按这里写的算。

## 1. 给谁用

三个人以内的小组、在自己的电脑上查自己仓库里的文档（`.md` / `.txt`），不上网、不建服务、不装数据库。
典型场景：作业写完了想确认「某个词到底在哪个文件里出现过」，或者「哪份文档里出现得最多」。

## 2. 输入

- 一个目录（可以有任意层子目录），例如 `python minisearch.py index docs`
- 只处理后缀为 `.md` 和 `.txt` 的文件（大小写不敏感，`.MD` 也算）
- 文件编码按 UTF-8 读；非 UTF-8 的文件跳过并警告，不中断
- 空文件正常索引，记 0 行 0 词 0 字

## 3. 三类查询

1. **某个词在哪些文件里出现过** —— `search` 列出所有命中的文件
2. **出现了几次** —— 每行第一段给出次数，并按次数从多到少排序
3. **第一次出现在哪一行** —— 每行第二段给出该文件里第一处匹配的原文（超过 80 字截断）

## 4. 多少条算通过

- `tests.md` 里的 8 条测试**全部通过**，其中 3 条是异常场景（目录不存在、空目录/空文件、非 UTF-8）
- 同一个目录连续跑两次 `index`，两次生成的 `index.json` **逐字节相同**
- 三条命令的退出码符合 README 的表（0 / 1 / 2）

## 5. 明确不做

1. **不做中文分词** —— 不引入 jieba 之类的分词库，中文按整串统计；`words` 只按空白切分
2. **不做模糊匹配 / 正则 / 同义词** —— `search` 只做子串包含（大小写不敏感）
3. **不建倒排索引、不做增量更新** —— 每次都全量重扫，`index.json` 整体重写
4. **不提供 Web 界面、不提供 HTTP 接口** —— 只有命令行
5. **不支持 PDF / Word / 图片** —— 只认纯文本
6. **不做高亮、不输出上下文多行** —— 每个文件只给第一处匹配行

## 6. 已知限制

- 中文不分词导致词频统计对中文没有参考价值（只对英文/代码标识符有意义）
- 非 UTF-8 文件的内容不参与统计（会被整份跳过）
- 大目录会把所有文本读进内存，内存占用与文件总大小同阶
- `search` 必须在 `index.json` 所在目录执行
- 索引里只存统计结果，不存原文，所以 `search` 需要重新读源文件；源文件被删改后要重新 `index`
