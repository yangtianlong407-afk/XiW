# 错误处理记录（四条实测 + 一条附加）

测法：在 `groups/26级-D1/` 下用 Python 3.12 直接跑 `ask.py`，把 stdout 和 stderr 分开记录；
退出码用 `$LASTEXITCODE` 取。「连不上服务器」和「返回空内容」两条用 `tools/mock_llm.py` 起本地假模型复现，
不需要真 key、不花钱，换台机器也能重跑一遍。

## 1. 不设 key

```powershell
Remove-Item Env:LLM_API_KEY
python ask.py ask "典型使用场景是什么？"
```

- 退出码：1

**stdout**

```
（空）
```

**stderr**

```
缺少 LLM_API_KEY。设置方法：
  PowerShell:  $env:LLM_API_KEY="你的key"
  CMD:         set LLM_API_KEY=你的key
  （key 不要写进代码，也不要提交进仓库）
```

## 2. 没有 index.json

```powershell
Rename-Item index.json index.json.bak
python ask.py ask "典型使用场景是什么？"
```

- 退出码：1

**stdout**

```
（空）
```

缺少 index.json，请先运行：python minisearch.py index docs/
```

## 3. 连不上服务器（断网 / BASE_URL 写错）

$env:LLM_BASE_URL="http://127.0.0.1:8899"   # 没有服务在听
python ask.py ask "典型使用场景是什么？"

重试后仍失败：连不上服务器，检查网络或 LLM_BASE_URL
```

## 6. 附加：环境变量里含中文（照抄了「你的key」占位符）

```powershell
$env:LLM_API_KEY="你的key"      # 直接把文档里的占位符粘进来
python ask.py ask "中文为什么不分词？" --json
```

- 退出码：1

**stdout**

```
（空）
```

**stderr**

```
环境变量 LLM_API_KEY 里有非 ASCII 字符，请求发不出去。
  最常见的原因是照抄了文档里的占位符（比如「你的key」），或者多粘了中文说明。
  当前值：你的key
  请换成服务商给的真实值，例如：
    $env:LLM_API_KEY="sk-xxxxxxxxxxxxxxxx"
```

> 这条是真实踩到的：一开始没做校验时，HTTP 头按 latin-1 编码会抛
> `UnicodeEncodeError: 'latin-1' codec can't encode characters in position 7-8`，
> 甩出一大段 traceback。加了校验之后变成上面这一小段人话，退出码 1。

## 小结

六条都是**退出码 1、stdout 干净、stderr 一句人话、没有 traceback**。
在 `--json` 模式下也一样：错误信息走 stderr，stdout 不会出现半截 JSON，脚本解析不会崩。
